# 結果まとめ（2026-09-01 時点）

**目的**: 個別の日付ドキュメントに散っている測定結果を1枚に集める。
「何を確かめて、どうなったか」だけを載せ、手順や経緯は各ドキュメントに譲る。
時系列で流れを追いたいときは `docs/progress-log.md`、
要件と設計判断は `docs/PRD.md` を見る。

**読み方**: 主指標は **MAE（平均絶対誤差）**。予測が平均でいくらズレるかを、
値段そのものの単位で表したもの。**小さいほど良い。** シエンタは万円、
Craigslist は USD で測っている。単位が違うので、2つのデータセットの数字を
直接比べてはいけない。

---

## 1. 一言でいうと

**テキストに本当に情報がある場所では、LLM を挟むと既存の最良手法を上回る。
情報が無い場所では上回らない。** 中古車価格予測を題材に、それを同じ物差しで測り切った。

成果物は scikit-learn 互換のライブラリ `unfold` で、設計書の3本柱
（機能A・機能B・信頼度ルーティング）がすべて API になっている。

## 2. 受け入れ基準の達成状況

`docs/PRD.md` §8 で先に決めた合格ラインに対する現在地。

| | 基準 | 結果 | 判定 |
|---|---|---|---|
| S1 | 機能A が比較線を有意に下回る | 2,580.78 対 2,586.88（差 −6.10、振れ幅 ±32 以内） | **同着** |
| S2 | 機能A が未知車種名で文字TF-IDF に勝つ | 3,637.05 対 3,622.03（+15.03） | **未達** |
| S3 | 機能A が人手ルールに負けない | −163 USD | **達成** |
| S4 | 機能A が CAAFE に勝つ | 2,581 対 2,798（p=0.007、5/5 fold） | **達成** |
| S5 | TabPFN に勝つ | 12.21 対 12.95（シエンタ） | **達成** |
| S6 | 機能B が最良の単体モデルを有意に下回る | 1,980.68 対 2,591.58（p=0.016、5/5 fold） | **達成** |
| S7 | コストを提示できる | 機能B $0.0086〜0.0121/行、機能A フォールバック $0.0036/行 | **達成** |
| S8 | 来歴を辿れる | `explain` / `confidence` / `examples` / `cost` / `provenance` | **達成** |

**8項目中6つ達成、1つ同着、1つ未達。** 未達の S2 は、機能A の単一表現が
未知の車種名では文字 TF-IDF にわずかに及ばないというもの。ただし
**併用すれば未知 3,620.23 で同着になり、全体は最良 2,577.03** になるので、
使い方の指針が1つ増えたと読むのが正しい。

用語: **p 値**は「差がまぐれで出る確率」。0.05 未満なら偶然とは考えにくい、
というのが通例。**fold** は交差検証でデータを分けた組で、5-fold なら
5通りの分け方すべてで測る。「5/5 fold で勝ち」は全通りで勝ったという意味。

## 3. データセットごとの到達点

### シエンタ（単一車種・5,507行・日本語・万円）

| 手法 | MAE | 中央値 185.7 万円に対する誤差率 |
|---|---:|---:|
| 中央値を返すだけ | 64.57 | 34.8% |
| 線形回帰・従来列（**従来手法の再現**） | 22.76 | 12.3% |
| LightGBM・従来列 | 17.51 | 9.4% |
| ＋構造化列フル | 12.88 | 6.9% |
| **＋装備テキストの文字TF-IDF（最良）** | **12.21** | **6.6%** |
| TabPFN・構造化列フル＋埋め込み64次元 | 12.34 | 6.6% |
| 機能B（LLM が最終判断） | 12.85 | 6.9% |

**従来の線形回帰 22.76 から 12.21 へ、誤差をほぼ半分にした。**
ただし**この題材では LLM は効かない**（機能B 12.85 対 比較線 12.99）。

### Craigslist（複数車種・60,000行・英語・USD）

| 手法 | 全体 MAE | 既知の車種名 | 未知の車種名 |
|---|---:|---:|---:|
| B2 手書きルールで正規化 | 2,758.03 | 2,610.79 | 3,979.19 |
| C2 車種名の文字TF-IDF | 2,616.96 | 2,495.77 | 3,622.03 |
| D1 e5 埋め込み | 2,603.18 | 2,464.02 | 3,757.33 |
| D4 埋め込み＋文字TF-IDF | 2,586.88 | 2,454.27 | 3,686.71 |
| **F 機能A（埋め込み列）** | **2,580.78** | **2,453.42** | 3,637.05 |

## 4. 機能ごとの結果

### 機能A（`Feature`）— 非構造列を型付き列にする

**人手ルールと同じところに、半分の手数で着地する。**
手書きの正規表現を書かず、追加依存のない既定エンコーダ1本（文字 n-gram TF-IDF + SVD256）で
D4（埋め込みと文字TF-IDF の併用）と同着になる。

仕様書の前提を1つ覆した。**教師ラベルは「値の名前だけ・ラベル0件」が最も良く、
人手ラベル200件より 2.31 万円良い**（`docs/2026-08-29-feature-skeleton.md`）。
ラベル作成という工程は要らなかった。

**LLM フォールバック（設計書05）**: 確信度の低い15%だけ LLM に回すと、
正解率 **0.873 → 0.942**。**回した行は全問正解**だった
（`docs/2026-09-01-feature-fallback.md`）。「迷った行だけ LLM」という設計が裏付けられた。

| エスカレーション率 | 正解率 | 費用 |
|---:|---:|---:|
| 0%（LLM なし） | 0.790 | $0 |
| 5% | 0.833 | $0.106 |
| 15% | 0.853 | $0.215 |
| 30% | 0.885 | $0.333 |

### 機能B（`LLMPredictor`）— 統計モデルの上に乗る最終判断

**複数車種では合格、単一車種では不合格。**

| | 機能B | 比較線 | 差 |
|---|---:|---:|---:|
| Craigslist（600行） | **1,980.68** | 2,591.58 | **−23.6%**（p=0.016、5/5 fold） |
| シエンタ（300行） | 12.85 | 12.99 | −1.1%（有意でない） |

差の理由ははっきりしている。**LLM の修正が当たる率**が、シエンタ 46%（コイン投げ）に対し
Craigslist 67%。**テキストに情報がない場所では LLM も効かない。**
事前スクリーニング（`unfold.screen()`）が、この見極めを測定前に行う道具にあたる。

| データ | 列 | テキスト寄与率 | 判定 |
|---|---|---:|---|
| シエンタ | 装備テキスト | 4.3% | 効きにくい |
| Craigslist | 車種名 | **15.4%** | 試す価値あり |
| Craigslist | 説明文 | 3.7% | 効きにくい |

### 信頼度ルーティング（`AdaptivePredictor`）— 全行を LLM に投げない

6万行に機能B を素で当てると **$516・17時間**かかるため、絞る仕組みは必須だった。
最も良い信号は「**LightGBM と XGBoost の食い違い**」＝統計モデル自身が迷っている行。

| LLM に回す割合 | MAE | 費用 | 推定時間 |
|---:|---:|---:|---:|
| 0% | 3,042.6 | $0 | 24 秒 |
| 10% | 2,907.3 | $0.52 | 61 秒 |
| 30% | 2,673.5 | $1.57 | 130 秒 |
| 50% | 2,581.1 | $2.62 | 199 秒 |
| 100% | 2,265.5 | $5.23 | 369 秒 |

**精度は割合に対してほぼ線形に効き、費用も線形。**
どこで止めるかは予算で決められる、という形になった。

## 5. 費用とレイテンシ（応答時間）

| 項目 | 実測 |
|---|---|
| 機能B 1行あたり | $0.0086〜0.0121 |
| 機能A フォールバック 1行あたり | $0.0036 |
| LLM 1件の応答時間（中央値） | 4.6 秒 |
| 統計モデルだけの応答 | 6 ミリ秒 |
| 統計モデルの fit + 近傍索引の構築 | 23.9 秒 |

**1件あたりの応答時間は並列数を上げても縮まない**（API 側の素の速度）。
一方**全体時間は並列数にほぼ反比例し、費用は並列数を変えても同じ**。

| 並列数 | 全体（15行） | 1行あたり |
|---:|---:|---:|
| 1 | 88.6 秒 | 5.91 秒 |
| 4 | 23.9 秒 | 1.60 秒 |
| 8 | 15.5 秒 | 1.03 秒 |

**バッチ処理なら問題ないが、対話的な用途（1台を画面で査定する）では 4.6 秒は長い。**
ここで信頼度ルーティングが効く。

## 6. 見つけた落とし穴

測定を良く見せてしまう罠を2件見つけ、どちらも**部分集合に分けて採点する**ことで検出した。

**1. 同一車の重複出稿（42%）。** 同じ VIN が最大 261 件あり価格まで同一。
放置してランダム分割の交差検証をすると、同じ車が train と test の両方に入る。
MAE が 4.2%・R² が 0.03 だけ良く見える。→ 1台1行に潰す処理を入れ、
検知自体を `unfold/leakage.py` としてライブラリの責務にした。

**2. 説明文に価格が書かれていた。** 自由記述を渡したら 40% 改善したので疑ったところ、
採点した600行のうち **262行（43.7%）の説明文に価格そのものが書かれていた**。

| 構成 | 全600行 | 価格記載あり(262) | 記載なし(338) |
|---|---:|---:|---:|
| 説明文なし | 2,335.32 | 2,035.29 | 2,567.89 |
| 説明文あり・伏字なし【無効】 | 1,545.86 | 718.65 | 2,187.07 |
| **説明文あり・伏字あり** | **1,980.68** | 1,738.89 | 2,168.10 |

**価格記載のある行だけ 65% 改善**という偏りが動かぬ証拠になった。
→ `mask_amounts()` で既定で伏せる形にし、これもライブラリ側の責務にした。
出品・求人・不動産など、自由記述に答えが書かれるデータでは常に起きるため。

**伏せて測り直しても 23.6% の改善が残り、効果は本物**だと確認できている。

### 撤回した結論が1件

前日に立てた「**弱い証拠は LLM を汚染する**」という一般則は、複数車種では
再現せず符号も逆だった。**シエンタ固有の現象**であり、一般則ではなかったので撤回した。

### 実施不能と判定した項目が1件

画像モダリティ（P5）は、着手前に15分で画像URLの生存確認をしたところ
**100件中100件が 404** だった。半日〜1日の無駄を回避できた。

## 7. 実行環境

**測定は計算ノード（Ubuntu 24.04 / 16 vCPU / 64GB）で行う。**
2026-09-01 に手元の Mac から移行した（`docs/2026-09-01-migration.md`）。

移行の決め手は CPU の速さではなく、**17時間のジョブをノートPCで走らせられない**こと。
実測の速度差は 1.5〜2.2 倍で、事前の見積もり（3〜5倍）には届かなかった。

**注意: 機械をまたぐと値が僅かにズレる。** 同じ 60,000行・5-fold を両環境で回すと、
A2（13列）は完全一致するが、C2（1,013列）は 2,616.96 対 2,619.04 で 2.08 ずれる。
データ・スレッド数・TF-IDF 行列はすべて同一であることを確認済みで、
原因は LightGBM のバイナリ差（AVX2 対 AVX-512、clang 対 gcc）。
ズレは 0.079% で fold 間のばらつき（±22〜24）より1桁小さいが、
**機械をまたいだ数値を同じ表に並べてはいけない。**

## 8. 残っている宿題

- **leaderboard に実行環境の列を足す。** 上記のバイナリ差を記録上で辻褄合わせするため
- **主要な行をノードで測り直す。** 既存の行はすべて Mac 実測のもの
- **予測区間を出すか。** 点推定だけでなく幅で答えるか
- **特徴量のバージョン管理。** 3ヶ月後の再実行で同じ数字が出るか（S8 の未着手部分）
- **画像モダリティ。** 実施不能。API の設計だけ残す案が推奨

## 通して言えること

- **効く条件つきで示せた。** テキストに本当に情報がある場所では既存の最良手法を上回り、
  飾りでしかない場所では上回らない。どちらも同じ物差しで測った
- **良すぎる結果は必ず疑う。** リークを2件見つけ、どちらも部分集合に分けて採点することで検出した
- **間違った一般化は撤回する。** アブレーションの結論を1件、実測に基づいて訂正した
- **着手前に前提を15分で確認する。** 画像URLの生存確認がこれにあたり、
  最大の作業項目を1つ、無駄になる前に落とせた
